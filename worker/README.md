# KBO 경기 일정 중계기 (선택)

> **먼저 읽어주세요 — 이걸 배포하지 않아도 일정은 나옵니다.**
>
> GitHub Actions가 하루 두 번 KBO 일정을 받아 `data/games.json`에 커밋합니다
> (`.github/workflows/games.yml`). 계정도, 설치도, 설정도 필요 없습니다.
> 이 중계기는 **분 단위의 실시간이 필요해졌을 때만** 배포하면 됩니다.
>
> 지금 일정이 안 뜬다면 이 문서가 아니라 저장소의 **Actions → 경기 일정 받기**를
> 먼저 보세요.

## 이건 언제 쓰나

Actions 방식은 하루 두 번입니다. 그 사이에 바뀐 것(당일 취소·지연·시간 변경)은
다음 실행 때까지 반영되지 않습니다. 그때그때 바로 반영되어야 한다면 이 중계기를
띄우고 주소를 넣으면 됩니다. 앱은 중계기를 먼저 보고, 실패하면 조용히
`data/games.json`으로 내려갑니다. **중계기가 죽어도 앱은 삽니다.**

브라우저에서 KBO를 직접 부를 수는 없습니다. KBO 쪽이 CORS 헤더를 주지 않아
브라우저가 막습니다. 그래서 중계기가 필요합니다.

## 배포 (5분, 하고 싶을 때만)

Cloudflare 계정이 필요합니다. 무료 요금제로 충분합니다.

```bash
npm install -g wrangler     # 한 번만
cd worker
wrangler login              # 브라우저가 열립니다
wrangler deploy
```

배포가 끝나면 이런 주소가 나옵니다:

```
https://kbo-schedule.<your-subdomain>.workers.dev
```

## 앱에 연결

`js/config.js`의 `gamesProxyUrl`에 그 주소를 넣습니다.

```js
gamesProxyUrl: 'https://kbo-schedule.your-subdomain.workers.dev',
```

넣고 커밋하면 끝입니다. 앱은 이 주소를 먼저 보고, 실패하면 번들된
`data/games.json`으로 내려갑니다. Actions는 그대로 두세요 — 중계기가 멈췄을 때
받아 주는 바닥입니다.

## 확인

배포 직후 브라우저에서 열어보세요.

| 주소 | 하는 일 |
|---|---|
| `/` | 이번 달 일정 |
| `/?month=2026-10` | 특정 달 |
| `/?stadium=gwangju` | 광주 경기만 |
| `/?debug=1` | KBO가 준 응답 원본 |

`games`에 경기가 들어 있으면 성공입니다.

## 배포 전에 확인해 둔 것

`wrangler dev --local`로 실제로 띄워서 확인했습니다.

- 빌드 통과 (8.8 KiB)
- `/` `?month=` `?stadium=` `?debug=1` 모두 응답
- 잘못된 `month` → 400, `OPTIONS` 프리플라이트 → 200
- CORS·캐시 헤더 정상
- **KBO가 막혔을 때도 200으로 빈 목록 + 사유를 돌려줍니다** (앱이 죽지 않습니다)

KBO 호출만은 확인하지 못했습니다. 작업 환경에서 그 주소가 막혀 있어
`?debug=1`이 이렇게 나왔습니다:

```json
{ "ok": false, "status": 403,
  "bodyHead": "Host not in allowlist: www.koreabaseball.com ..." }
```

**막은 것은 작업 환경이지 KBO가 아닙니다.** 요청 자체는 제대로 나갑니다.
Cloudflare에서는 그 제한이 없으니 실제로 닿습니다.

Actions 러너에는 그 제한이 없습니다. 그래서 `경기 일정 받기` 워크플로의 로그가
KBO 응답을 실제로 확인할 수 있는 첫 자리입니다 — 표 읽기가 어긋나면 거기서
먼저 드러납니다.

## games가 비어 있다면

**이게 가장 있을 법한 문제입니다.** KBO 표의 칸 구성은 직접 불러봐야 알 수
있는데, 이 코드는 그 확인 없이 쓰였습니다. 생김새로 값을 찾도록(날짜꼴,
시각꼴, 구장 이름) 만들어서 웬만하면 읽히지만, 어긋날 수 있습니다.

1. `/?debug=1`을 열어 봅니다. 성공이면 `raw`(KBO 원본)와 `parsed`(읽어낸 경기 수)가,
   실패면 `status`·`error`·`bodyHead`가 나옵니다. 진단할 때는 캐시를 건너뜁니다.
2. `raw.rows[].row[].Text`에 뭐가 들어 있는지 확인합니다.
3. `kbo-schedule.js`의 `pickCells()`만 고치면 됩니다. 나머지는 손댈 일이 없습니다.
4. `node scripts/test-worker.mjs`로 시험합니다. 견본을 실제 모양으로 바꿔
   두면 다음에 또 깨졌을 때 바로 알 수 있습니다.

같은 표 읽기 코드를 Actions 쪽(`scripts/fetch-games.mjs`)도 씁니다. 한 곳을
고치면 양쪽이 같이 고쳐집니다.

`raw`를 그대로 붙여주시면 제가 맞춰 고치겠습니다.

## 지키는 것

**경기 취소를 추론하지 않습니다.** 공식 표에 "취소"라고 적혀 있을 때만
취소로 옮깁니다. 비가 온다고, 정황이 그렇다고 취소로 바꾸지 않습니다.
아무 말도 없으면 `unknown`이고, 앱은 공식 발표 링크를 함께 보여줍니다.

## 비용

10분 캐시가 걸려 있어 한 달 호출이 무료 한도(하루 10만 건) 근처에도 가지
않습니다.
