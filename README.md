# ⚾ KBO 명당지도

> 야구장 가기 전에, 내 자리를 미리 본다.

야구장 좌석 지도를 보면서 내가 앉을 자리를 고르는 서비스입니다.
목록이 아니라 **지도가 첫 화면**입니다.

## 실행

빌드 도구가 없습니다. 정적 파일을 그대로 서빙하면 됩니다.

```bash
python3 -m http.server 8765
# http://127.0.0.1:8765/
```

## 구조

```
index.html            홈 — 오늘 경기 / 구장 찾기 / 나에게 맞는 명당
stadium.html          구장 상세 (앱 본체). ?id=gwangju&tab=seats&prefs=focus,cheer
css/base.css          디자인 토큰 (딥네이비 / 화이트 / 레드 포인트)
js/config.js          바뀔 수 있는 값 전부 (URL·공유 문구·날씨 설정)
js/services/          dataService · weatherService · gameService · shareService
js/recommend.js       맞춤 명당 추천 (데이터 기반 가중합, AI 아님)
js/ui/render.js       화면 그리기 공통 도구
data/*.json           모든 콘텐츠. UI는 이 파일만 본다.
map/                  구장별 좌석 SVG (예정)
```

새 구장을 추가할 때 **코드를 복제하지 않습니다.** `data/*.json`에 항목만 추가합니다.

## 데이터 원칙 (가장 중요)

이 서비스는 정보 신뢰성을 최우선으로 합니다. 코드가 아니라 **데이터 구조가** 이를
강제합니다.

- 값이 `null`이면 UI는 **"정보 준비 중"**을 표시합니다. 빈 화면도, 지어낸 값도 없습니다.
- 각 레코드는 `verified`(필드별 확인 여부), `sources`, `updatedAt`을 가집니다.
- **날씨와 경기 취소는 완전히 분리합니다.** 날씨가 나빠도 경기 상태를 단정하지 않고,
  기본값은 `🟡 공식 발표 확인 필요`이며 항상 KBO 공식 링크를 함께 보여줍니다.
- **직관지수**는 이 서비스의 자체 참고 지표입니다. 공식 경기 취소 확률이 아닙니다.
- **좌석 점수**는 직관 경험 기반의 참고 지표입니다. 공식 평가가 아니며, 화면에
  항상 그렇게 표기합니다.
- **시야 사진은 실제 촬영본만** 씁니다. 생성 이미지를 실제 시야처럼 쓰지 않습니다.

## 현재 데이터 상태 (광주-기아 챔피언스 필드)

| 항목 | 상태 |
|---|---|
| 구장명·도시·홈팀·주소·개장연도 | 확인됨 (2차 출처 일치) |
| 좌석 수, 좌표, 예매 링크 | **미확인** — `verified:false` 또는 `null` |
| 좌석 블록 배치·가격·평가 | **없음** — 화면은 "준비 중" |
| 시야 사진 | **없음** |
| 먹거리·굿즈샵·편의시설·교통 | **없음** (주차 면수만 미확인 상태로 보관) |
| 경기 일정·순위 | **없음** — KBO 공개 API가 없어 큐레이션 필요 |

공식 홈페이지(`tigers.co.kr`)는 개발 환경의 네트워크 정책으로 직접 확인하지
못했습니다. 1차 출처 확인 후 채워야 합니다.

## 배포

GitHub Pages, `main` 브랜치 루트. 빌드 단계가 없습니다.

```
https://minimalbreeze.github.io/kbo-myeongdang/
```

`.nojekyll`을 두어 Jekyll 처리를 끕니다(순수 정적 파일이라 거칠 이유가 없습니다).

**커스텀 도메인을 붙일 때** 바꿔야 하는 곳은 네 군데입니다.
`js/config.js`의 `siteUrl`, `index.html`·`stadium.html`의 `canonical`/`og:url`,
`robots.txt`의 Sitemap 줄, `sitemap.xml`의 `<loc>`.

### 공유 미리보기 이미지

카카오·X 같은 스크래퍼는 **이미지 URL을 키로** 캐시하고 오래 재확인하지 않습니다.
`og-image.png`의 내용만 바꾸면 공유 카드는 몇 주 동안 옛 그림 그대로입니다.
그림을 바꿀 때는 **파일명을 `og-image-v2.png`처럼 올리고**, 옛 파일은 남겨두세요
(이미 퍼진 링크가 깨지지 않도록).

### 아이콘

`icon.svg`(파비콘/Android any), `icon-180.png`(iOS 홈 화면),
`icon-192.png`/`icon-512.png`(Android any), `icon-512-maskable.png`(Android adaptive,
안전 영역 확보) 다섯 가지를 함께 유지합니다. 아이콘을 바꿀 때는 전부 다시 만들어야 합니다.
심볼은 **위에서 내려다본 좌석 그릇이고, 붉은 띠 하나가 "명당"** 입니다 — 이 서비스의
핵심이 지도라서 야구공이 아니라 지도를 씁니다.

### 검색 노출

지금은 홈 한 장만 색인 대상입니다. `stadium.html`은 `noindex`입니다 —
내용이 거의 비어 있는 페이지를 색인시키지 않기 위해서입니다.
구장 데이터가 채워지면 `/stadium/gwangju/` 같은 **검색용 정적 페이지**를
데이터에서 생성해 `sitemap.xml`에 함께 넣고, 그때 이 `noindex`를 걷어냅니다.

## 데이터 채우기

내용은 전부 `data/*.json`에 손으로 넣습니다. 코드는 건드리지 않습니다.

### 넣기 전에

값을 **모르면 넣지 마세요.** `null`로 두면 화면이 "정보 준비 중"이라고 말합니다.
지어낸 값보다 빈 값이 낫습니다.

### 넣은 뒤에는 반드시

```bash
node scripts/validate-data.mjs
```

없는 구장 id, 음수 가격, 어긋난 날짜 형식, 범위를 벗어난 점수, 같은 시각에 두 번
잡힌 경기, 쉼표 빠진 JSON(몇 번째 줄인지도 알려줍니다) 같은 것을 잡습니다.
CI에서도 같은 검사가 돌아서, 통과 못 하면 합칠 수 없습니다.

### 자주 넣게 될 세 가지

**경기** (`data/games.json`의 `games` 배열) — **손으로 넣지 않습니다.**

GitHub Actions가 하루 두 번(한국시간 06:10·17:10) KBO 공식 일정을 받아
이 파일에 커밋합니다(`.github/workflows/games.yml`). 손으로 고치면 다음
실행에 덮어쓰입니다. 지금 바로 받고 싶으면 저장소의 **Actions → 경기 일정 받기
→ Run workflow**를 누르면 됩니다. 모양은 이렇습니다.

```jsonc
{
  "date": "2026-09-15",     // YYYY-MM-DD
  "time": "18:30",          // HH:MM
  "stadiumId": "gwangju",
  "homeName": "KIA 타이거즈",
  "awayName": "LG 트윈스",
  "status": "unknown"       // 기본값. 취소·지연은 공식 발표를 본 뒤에만 바꾼다
}
```

`status`는 공식 표에 적힌 말만 옮깁니다. 날씨가 나빠도 경기 진행 여부는
공식 발표가 정합니다. 모르면 `unknown`이고, 화면이 KBO 공식 링크를 함께 띄웁니다.

분 단위의 실시간이 필요해지면 `worker/`의 중계기를 배포하는 선택지가 따로
있습니다(`worker/README.md`). 없어도 일정은 나옵니다.

**좌석 평가** (`data/seats.json`의 해당 구장 `sections` 배열)

```jsonc
{
  "section": "k8-120",
  "seatName": "K8석 120블록",
  "viewScore": 4, "gameScore": 3, "cheerScore": 5, "photoScore": 2,
  "valueScore": 4, "sunScore": 3, "weatherScore": 3, "facilityScore": 3,
  "description": "응원단상이 바로 앞이라 소리가 크다",
  "price": "성인 15000",
  "viewImage": null,        // 실제로 찍은 사진만. 없으면 null
  "viewSource": null,       // 사진이 있으면 누가 찍었는지 반드시 함께
  "updatedAt": "2026-09-15"
}
```

점수는 **0~5, 높을수록 좋음**입니다. `sunScore` 5는 "햇빛 영향이 적다",
`weatherScore` 5는 "비바람 영향이 적다"는 뜻입니다. 모르는 항목은 빼면 됩니다 —
빠진 항목은 추천 계산에서 그냥 빠지지, 0점으로 세지 않습니다.

**좌석 지도 구역** (`data/map/<구장id>.json`의 `zones`)

각도는 0이 중견수 방향, 90이 1루측, 180이 홈 뒤, 270이 3루측입니다.
`r0`이 안쪽, `r1`이 바깥쪽 반지름이고 `r0 < r1`이어야 합니다.
공식 좌석도로 확인했으면 `"verified": true`로 올리세요 — 지도에서 선명해집니다.
아직이면 `confidence`를 `corroborated`(여러 곳 일치) 또는 `unplaced`(위치 미확인)로
두고, `why`에 왜 아직 확인 중인지 한 줄 적습니다. 그 문장이 화면에 그대로 나옵니다.

## 홈이냐 원정이냐

**명당은 응원하는 쪽에 따라 다릅니다.** 광주는 3루가 홈(KIA), 1루가 원정입니다.
원정 팬에게 3루 응원석은 명당이 아니라 피해야 할 자리입니다.

지도 위 `🏠 홈 팬` / `✈️ 원정 팬` 버튼으로 바꾸면 🏅 핀이 따라 바뀝니다.
상대 쪽 응원석을 열면 시트에 빨간 배지로 `상대 쪽`이라고 알려줍니다.

좌석과 지도 구역 모두 `side`를 가집니다 — `home` / `away` / `neutral`.
**구장마다 다르므로** 다른 구장을 추가할 때 반드시 확인해서 넣어야 합니다.

## 이벤트 존 (`data/events.json`)

구장 안의 포토존·체험존입니다. 위치가 확인된 것만 넣습니다.
행사는 시즌·경기마다 바뀌므로 화면에도 그렇게 적습니다.

## 명당은 어디서 온 정보인가

`data/seats.json`의 구역별 점수는 **여러 관람 후기에서 공통으로 언급되는 내용**만
모은 것입니다. 공식 평가가 아닙니다. 각 구역에 `basis`(왜 그렇게 보는지 한 줄)와
`sources`(출처 링크)를 함께 두고, 화면에서도 그대로 보여줍니다.

출처가 말하지 않은 항목은 **비워 둡니다.** 화면은 그 자리에 "후기에 언급 없음"이라고
적고, 추천 계산에서도 그냥 빠집니다 — 모르는 것을 좋다고 치지 않습니다.

### 실제 시야 사진은 밖에 있습니다

**자리어때**(`myseatcheck.com`)에 이 구장 구역별 시야 사진이 9,000장 넘게 올라와
있습니다. 우리 개략도보다 정확하므로, 좌석 시트에서 그쪽으로 보내는 링크를
함께 답니다(`viewPhotosUrl`). 사진을 가져오지 않고 링크만 겁니다.

### 추천 점수 계산 (`js/recommend.js`)

- **기준 점수(0~75)** 가중 평균 × coverage(그 취향에 대해 얼마나 알고 있는지).
  모르는 축이 많으면 점수가 내려갑니다.
- **근거 가산점(0~25)** 출처들이 "이건 무엇에 좋은 자리"라고 공통으로 말한
  경우(`myeongdangFor`)에만 붙습니다.

처음에는 "있는 점수만 골라 평균"을 냈는데, 그러면 한 축만 높은 구역이 실제로 맞는
구역을 이겼습니다 — 응원 기준인데 챔피언석이 1위로 나왔습니다(응원 점수가 없어서
경기 몰입도 하나만 평균이 됐기 때문). 그래서 취향별 1위를
`scripts/test-recommend.mjs`에 고정해 두었습니다.

## 지도의 연출

한강 불꽃축제 명당지도를 보면, 까만 지도 위에서 불꽃이 터지고 그 주위로 빛의 고리가
퍼집니다. 한눈에 **모두가 보려는 그것이 어디인지**, 그리고 **내가 얼마나 가까운지**가
읽힙니다. 각도가 아니라 그 연출이 핵심이었습니다.

야구장에서 그 자리는 그라운드입니다. 그래서

- 바탕을 거의 검게 두고, **그라운드가 빛납니다** (`#kbo-burst` 방사형 그라디언트)
- 홈플레이트에서 **거리 고리**가 퍼집니다. 실측이 아니므로 미터를 적지 않습니다 —
  눈으로 재라고 두는 것이지 읽으라고 두는 것이 아닙니다(참고한 화면의 고리에도
  글자가 없습니다)
- 명당은 배지가 아니라 **빛나는 핀**으로 세웁니다 (`#kbo-glow` 필터)

핀은 라벨 **왼쪽**에 붙입니다. 위에 뒀더니 바로 윗 띠와 겹쳤습니다. 글자 폭은
한글 기준 글꼴 크기의 약 0.98배로 잡습니다 — 0.62로 잡았다가 핀이 글자를 덮었습니다.

## 이 자리에서 보기 (`js/ui/seatView.js`)

좌석 지도가 "어디에 앉을까"라면, 이 화면은 **"거기 앉으면 뭐가 보이나"** 입니다.
그라운드에 선수를 세워두고, 손가락으로 끌어 둘러볼 수 있습니다.
라이브러리를 쓰지 않습니다 — 원근 투영은 나눗셈 한 번이면 됩니다.

**사진이 아니라 기하 개략도입니다.** 베이스 27.43m 간격, 마운드 18.44m, 수비 위치는
야구의 규격이라 지어낸 값이 아니지만, 이 구장의 실제 외야 거리와 스탠드 높이는
실측이 아닙니다. 화면에 그렇게 적어 두었고, **실제 시야 사진(`viewImage`)이 있으면
그쪽을 먼저 보여줍니다.**

만들면서 배운 것 넷

- **좌석 거리를 반지름에 그냥 비례시키면 안 됩니다.** 지도는 개략도라 관중석이
  필드보다 크게 그려져 있어서, 그대로 환산하면 홈 뒤 자리가 50m 넘게 멀어지고
  그라운드가 점처럼 작아집니다. 관중석 반지름 구간을 실제 좌석 거리
  구간(18m~135m)에 맞춰 폅니다.
- **내가 앉은 쪽 백스톱은 그리면 안 됩니다.** 그 뒤에 앉아 있으니 실제로 안 보이고,
  그리면 화면을 통째로 가립니다(챔피언석에서 그라운드가 사라졌었습니다).
  시선 반대편 105° 밖만 그립니다.
- 선수는 **먼 쪽부터** 그려야 가까운 선수가 위에 옵니다.
- **꼭짓점 하나가 카메라 뒤에 있다고 도형을 버리면 안 됩니다.** 옆자리나 외야에서는
  홈플레이트가 시야 밖이라 잔디가 통째로 사라졌습니다. 버리는 대신 근평면에서
  잘라 나머지를 그립니다(Sutherland–Hodgman).

## 지도

위에서 내려다본 평면도 하나만 그립니다. 기울여 보는 입체도 만들어 봤는데, 세로가
눌려 홈 뒤 구역 글자가 서로 붙고 보기에도 나아지지 않아 걷어냈습니다.
**자리에서 실제로 어떻게 보이는지는 "이 자리에서 보기"가 맡습니다** — 그게 원래
하고 싶었던 일이고, 지도를 기울이는 것으로는 그 답이 안 나옵니다.

## 오프라인 (`sw.js`)

경기 날 구장 주변은 사람이 몰려 네트워크가 제일 안 터지는데, 정작 좌석 지도가
필요한 순간이 거기입니다. 그래서 한 번 본 화면과 구장 데이터는 오프라인에서도 열립니다.

| 대상 | 전략 | 이유 |
|---|---|---|
| 날씨 API (다른 출처) | **캐시하지 않음** | 오래된 날씨를 지금 날씨처럼 보여주지 않는다 |
| 화면·코드·`data/*.json` | network-first | 온라인이면 항상 최신. 캐시 때문에 옛 버전이 붙박이지 않는다 |
| 아이콘·이미지 | cache-first | 거의 안 바뀌고, 바꿀 때는 파일명을 올리는 것이 이 저장소 규칙이다 |

오프라인이면 날씨 자리는 값을 비우고 되돌아갑니다 — 실패를 감추지 않습니다.

코드를 배포한 뒤 캐시를 확실히 갈아치워야 할 때는 `sw.js`의 `VERSION`을 올리세요.
옛 캐시는 `activate`에서 지워집니다.

## 사용자 제보

지도는 비어 있는 곳이 많고, 그 빈칸은 실제로 가본 사람만 채울 수 있습니다.
한강 불꽃축제 명당지도가 같은 문제를 사용자 제보로 풀었습니다.

지금은 **외부 의존성 없이** 동작합니다. 앱 안에서 폼(`js/ui/report.js`)을 채우면
정리된 글이 만들어지고, 공유 시트나 클립보드로 운영자에게 전달됩니다.
로그인도 서버도 필요 없고, 작성 중인 내용은 localStorage에 남아 사라지지 않습니다.

받는 곳이 생기면 `js/config.js`의 `report`만 채우면 됩니다.

```js
report: {
  url: '',    // 구글폼 등 웹 폼 주소 → "웹 폼으로 제보하기" 버튼이 생긴다
  email: '',  // 채우면 "메일로 보내기" 선택지가 생긴다
}
```

제보받은 내용은 확인 전까지 지도에 **"확인 중"**으로 표시되고, 공식 정보와
사용자 제보를 화면에서 구분합니다.

## 날씨 API

1단계는 **Open-Meteo**(API 키 불필요, CORS 허용)를 씁니다. 키가 필요한
기상청 단기예보로 바꿀 때는 `config.js`의 `weather.weatherProxyUrl`에
Cloudflare Worker 주소를 넣습니다 — **키를 클라이언트에 두지 않습니다.**
