# ⚾ KBO 명당지도

> 야구장 가기 전에, 내 자리를 미리 본다.

야구장 좌석 지도를 보면서 내가 앉을 자리를 고르는 서비스입니다.
목록이 아니라 **지도가 첫 화면**입니다.

## 실행

빌드 도구가 없습니다. 정적 파일을 그대로 서빙하면 됩니다.

```bash
python3 -m http.server 8765
# http://127.0.0.1:8765/
```

## 구조

```
index.html            홈 — 오늘 경기 / 구장 찾기 / 나에게 맞는 명당
stadium.html          구장 상세 (앱 본체). ?id=gwangju&tab=seats&prefs=focus,cheer
css/base.css          디자인 토큰 (딥네이비 / 화이트 / 레드 포인트)
js/config.js          바뀔 수 있는 값 전부 (URL·공유 문구·날씨 설정)
js/services/          dataService · weatherService · gameService · shareService
js/recommend.js       맞춤 명당 추천 (데이터 기반 가중합, AI 아님)
js/ui/render.js       화면 그리기 공통 도구
data/*.json           모든 콘텐츠. UI는 이 파일만 본다.
map/                  구장별 좌석 SVG (예정)
```

새 구장을 추가할 때 **코드를 복제하지 않습니다.** `data/*.json`에 항목만 추가합니다.

## 데이터 원칙 (가장 중요)

이 서비스는 정보 신뢰성을 최우선으로 합니다. 코드가 아니라 **데이터 구조가** 이를
강제합니다.

- 값이 `null`이면 UI는 **"정보 준비 중"**을 표시합니다. 빈 화면도, 지어낸 값도 없습니다.
- 각 레코드는 `verified`(필드별 확인 여부), `sources`, `updatedAt`을 가집니다.
- **날씨와 경기 취소는 완전히 분리합니다.** 날씨가 나빠도 경기 상태를 단정하지 않고,
  기본값은 `🟡 공식 발표 확인 필요`이며 항상 KBO 공식 링크를 함께 보여줍니다.
- **직관지수**는 이 서비스의 자체 참고 지표입니다. 공식 경기 취소 확률이 아닙니다.
- **좌석 점수**는 직관 경험 기반의 참고 지표입니다. 공식 평가가 아니며, 화면에
  항상 그렇게 표기합니다.
- **시야 사진은 실제 촬영본만** 씁니다. 생성 이미지를 실제 시야처럼 쓰지 않습니다.

## 현재 데이터 상태 (광주-기아 챔피언스 필드)

| 항목 | 상태 |
|---|---|
| 구장명·도시·홈팀·주소·개장연도 | 확인됨 (2차 출처 일치) |
| 좌석 수, 좌표, 예매 링크 | **미확인** — `verified:false` 또는 `null` |
| 좌석 블록 배치·가격·평가 | **없음** — 화면은 "준비 중" |
| 시야 사진 | **없음** |
| 먹거리·굿즈샵·편의시설·교통 | **없음** (주차 면수만 미확인 상태로 보관) |
| 경기 일정·순위 | **없음** — KBO 공개 API가 없어 큐레이션 필요 |

공식 홈페이지(`tigers.co.kr`)는 개발 환경의 네트워크 정책으로 직접 확인하지
못했습니다. 1차 출처 확인 후 채워야 합니다.

## 배포

GitHub Pages, `main` 브랜치 루트. 빌드 단계가 없습니다.

```
https://minimalbreeze.github.io/kbo-myeongdang/
```

`.nojekyll`을 두어 Jekyll 처리를 끕니다(순수 정적 파일이라 거칠 이유가 없습니다).

**커스텀 도메인을 붙일 때** 바꿔야 하는 곳은 네 군데입니다.
`js/config.js`의 `siteUrl`, `index.html`·`stadium.html`의 `canonical`/`og:url`,
`robots.txt`의 Sitemap 줄, `sitemap.xml`의 `<loc>`.

### 공유 미리보기 이미지

카카오·X 같은 스크래퍼는 **이미지 URL을 키로** 캐시하고 오래 재확인하지 않습니다.
`og-image.png`의 내용만 바꾸면 공유 카드는 몇 주 동안 옛 그림 그대로입니다.
그림을 바꿀 때는 **파일명을 `og-image-v2.png`처럼 올리고**, 옛 파일은 남겨두세요
(이미 퍼진 링크가 깨지지 않도록).

### 아이콘

`icon.svg`(파비콘/Android any), `icon-180.png`(iOS 홈 화면),
`icon-192.png`/`icon-512.png`(Android any), `icon-512-maskable.png`(Android adaptive,
안전 영역 확보) 다섯 가지를 함께 유지합니다. 아이콘을 바꿀 때는 전부 다시 만들어야 합니다.
심볼은 **위에서 내려다본 좌석 그릇이고, 붉은 띠 하나가 "명당"** 입니다 — 이 서비스의
핵심이 지도라서 야구공이 아니라 지도를 씁니다.

### 검색 노출

지금은 홈 한 장만 색인 대상입니다. `stadium.html`은 `noindex`입니다 —
내용이 거의 비어 있는 페이지를 색인시키지 않기 위해서입니다.
구장 데이터가 채워지면 `/stadium/gwangju/` 같은 **검색용 정적 페이지**를
데이터에서 생성해 `sitemap.xml`에 함께 넣고, 그때 이 `noindex`를 걷어냅니다.

## 사용자 제보

지도는 비어 있는 곳이 많고, 그 빈칸은 실제로 가본 사람만 채울 수 있습니다.
한강 불꽃축제 명당지도가 같은 문제를 사용자 제보로 풀었습니다.

지금은 **외부 의존성 없이** 동작합니다. 앱 안에서 폼(`js/ui/report.js`)을 채우면
정리된 글이 만들어지고, 공유 시트나 클립보드로 운영자에게 전달됩니다.
로그인도 서버도 필요 없고, 작성 중인 내용은 localStorage에 남아 사라지지 않습니다.

받는 곳이 생기면 `js/config.js`의 `report`만 채우면 됩니다.

```js
report: {
  url: '',    // 구글폼 등 웹 폼 주소 → "웹 폼으로 제보하기" 버튼이 생긴다
  email: '',  // 채우면 "메일로 보내기" 선택지가 생긴다
}
```

제보받은 내용은 확인 전까지 지도에 **"확인 중"**으로 표시되고, 공식 정보와
사용자 제보를 화면에서 구분합니다.

## 날씨 API

1단계는 **Open-Meteo**(API 키 불필요, CORS 허용)를 씁니다. 키가 필요한
기상청 단기예보로 바꿀 때는 `config.js`의 `weather.weatherProxyUrl`에
Cloudflare Worker 주소를 넣습니다 — **키를 클라이언트에 두지 않습니다.**
